CRM long run to 5,000 cumulative outer iterations

21,523,036 control volumes · CUDA · five-sweep block DP-LUR · bounded SA · Mach 0.85 · AOA 2.5° · ReMAC 5 million

Decision. The earlier 300-update endpoint was much too short to represent the final aerodynamic coefficients. Extending the same 1,278-iteration checkpoint by 3,722 updates reduced the residuals by factors of 4–12 and cut wing Cp RMSE from 0.2134 to 0.1003. Nevertheless, the last 500–1,000 updates still contain large CL/CD/CM motion, especially CM. The 5,000-iteration state is useful progress but remains unconverged and must not be selected as a certified NASA comparison.

Run definition and cost

  • Original checkpoint: 1,278 outer iterations; continuation: 3,722; cumulative total: 5,000.
  • Each outer iteration used five DP-LUR relaxation sweeps, for approximately 25,000 cumulative sweeps.
  • Continuation GPU compute time: 1,658.84 s (27 min 38.8 s); solver process time: 1,670.95 s (27 min 51.0 s).
  • Including the retained cold-start checkpoint, cumulative solve compute is about 35.8 min and cumulative solver process time about 37.1 min. The earlier 5.3-min mesh construction is separate.

Interpretation and next diagnostic

More iterations materially improve Cp and bring CL into the correct qualitative range, so the 300-update snapshot was indeed premature. However, 5,000 cumulative iterations do not establish a steady solution. The history is compatible with a very slowly damped mode, a pseudo-time oscillation, or a physical/numerical unsteady mode; one long trajectory is not enough to distinguish them.

Do not simply select the best-looking iteration. The next numerical experiment should first separate residual and load contributions by face family—procedural internal, 2:1 interface, stored cut face, wall, and far field—and correlate them with the CM oscillation. A shorter A/B using lower CFL or stronger pseudo-time damping can then test whether the mode is an implicit-iteration artifact before spending another full 5,000 updates.
