Procedural-AMR mean-flow block DP-LUR evaluation

Final disposition: numerically verified and retained as an opt-in research option; rejected as the current CRM load-convergence or accuracy fix.

Decision. Keep --dplur-block-coupling 1 for controlled future experiments, but leave its default off. The five-variable Euler coupling is correct and stable, yet the 21.5-million-control CRM test gained only 1–2% in residuals, did not materially suppress the load mode, improved wing Cp RMSE by only 0.129%, and cost 10.4% more GPU compute time. Cancel the proposal that this block action alone will recover the missing CRM lift or moment accuracy.

Question tested

The procedural Cartesian-AMR DP-LUR operator used a scalar Rusanov neighbor coefficient for each mean-flow equation. The explicit-face tetrahedral/hybrid solver already retained the cross-variable Euler coupling. This experiment asked whether transferring that five-variable coupling would damp the remaining low-frequency CRM mode without changing the nonlinear HLLC residual, mesh, SA equation, pseudo-time step, or surface-load calculation.

Implementation boundary

Added

A matrix-free action of the 3-D Euler normal-flux Jacobian on the neighbor conservative update. The Rusanov spectral term and Euler action form the first-order off-diagonal DP-LUR block.

Unchanged

HLLC nonlinear flux, viscous residual, bounded first-order SA face scheme, scalar viscous/SA implicit terms, five Jacobi sweeps, CFL, gradients, cut-face geometry, and load integration.

Default and scope

The switch defaults to zero and is accepted only with the DP-LUR integrator. Tetrahedral/hybrid support and the explicit-face solver are untouched.

Verification before the CRM comparison

  • Passed: CPU and CUDA builds and both CTests.
  • Passed: the analytic Euler Jacobian action against a central finite-difference derivative of the normal Euler flux.
  • Passed: option-off regression against the previous CUDA executable; maximum state difference after one update was 4.44×10−16.
  • Passed: 7,661,606-control CPU/CUDA uniform flow; maximum residual was about 4.93×10−13 and global imbalance below 6.62×10−14.
  • Passed: one block-coupled DP-LUR update agreed between CPU and CUDA to global relative L∞ 1.87×10−16.

Accuracy context

At this transient 300-update endpoint, NASA USM3D values are CL=0.54239, CD=0.02995, and CM=−0.06249. The block endpoint therefore remains −30.49% in CL, +3.12% in CD, and −37.80% relative to the NASA CM magnitude. The unusually close instantaneous CD is not evidence of convergence: CD, CL, and CM are all still moving, and the two branches follow essentially the same trajectory.

What this result cancels—and the next useful direction

This result cancels further tuning of the mean-flow Euler neighbor block as a stand-alone response to the CRM error. It does not invalidate the implementation: the analytic derivative, CPU/CUDA agreement, default regression, conservation audit, and stable full-scale run justify retaining it behind an explicit option.

The unresolved mode is now insensitive to both the bounded SA scalar repair and this mean-flow block neighbor action. The next high-value diagnostic should localize where the residual and load oscillation are generated—wall/cut faces, far field, or 2:1 interfaces—before adding another scheme. A face-family residual budget and load-correlated spatial residual map are more informative than immediately raising formal order or adding wall-normal cells.
