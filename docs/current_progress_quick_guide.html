L0 — numerical trust layer

L0 is the foundation, not an aerodynamic validation claim.

  • 3-D sphere conservation, positivity, restart, and CPU/CUDA regression pass.
  • Procedural CRM AMR geometry closure and uniform-flow preservation pass.
  • Fixed-step CPU/CUDA state differences are approximately machine precision.
  • Checkpoint reload, deterministic restart, and true-mesh plotting are retained.

Use L0 for

Software verification and development gates

Do not use L0 alone for

Claims that CRM CL, CD, or CM are accurate

Recent options: implemented does not mean promoted

Pressure normal probe

Stable and bounded, but changed wing Cp RMSE by only 0.018%.

Rejected as the primary accuracy fix

Bounded SA face scheme

Reduced SA residual, but did not materially change the load trajectory.

Retained as opt-in research

Block DP-LUR neighbor action

Verified Euler block action; about 10.4% more cost for only 1–2% residual improvement in the matched test.

Retained as opt-in research

The next L2 task

  1. Use the implemented residual and load budgets by internal, same-level/2:1 interface, cut, wall, far-field, and SA-source family.
  2. Track upper-wing shock position and sectional moment through the low-frequency cycle.
  3. Determine whether steady damping can reach a fixed point; otherwise develop true physical-time dual time.
  4. Port the verified 2-D DP-LUR reference to CUDA for NNLCI throughput.
  5. Only then reduce memory and design a targeted 30–40M-control refinement.
